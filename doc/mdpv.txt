1. INTRODUCTION                                       *mdpv* *mdpv-intro*

mdpv.nvim renders the current buffer in a browser tab, live, styled with
GitHub's actual CSS and GitHub's exact markup — alerts and Obsidian callouts,
task lists (clickable), wikilinks, footnotes, heading anchors, KaTeX math,
Mermaid diagrams, emoji shortcodes, frontmatter tables. It runs a pure-Lua
HTTP + SSE server on |vim.uv|: no Node, no Deno, no Python, no build step.

Any number of buffers can be previewed at once; each gets an unguessable URL
on one shared, localhost-only server.

==============================================================================
2. REQUIREMENTS                                          *mdpv-requirements*

- Neovim 0.12+.
- A browser, launched via |vim.ui.open()|.

Frontend libraries are vendored under `assets/vendor/` — there is nothing to
install or build.

==============================================================================
3. USAGE                                                          *:Preview*

  :Preview            open (or re-open) a preview for the current buffer
  :Preview!           force-preview a buffer whose filetype is not eligible
  :Preview close      close the current buffer's preview
  :Preview toggle     open/close the current buffer's preview
  :Preview list       list active previews and their URLs
  :Preview stop       close all previews and stop the server

Note: user commands must start with an uppercase letter (see
|user-cmd-abbrev|), so a literal `:preview` is not possible.

==============================================================================
4. CONFIGURATION                                              *mdpv-config*

Calling setup() is optional. Defaults: >lua

  require('mdpv').setup({
    host = '127.0.0.1',    -- interface to bind; keep loopback
    port = 0,              -- 0 = free ephemeral port (no conflicts)
    theme = 'auto',        -- 'auto' | 'light' | 'dark'
    debounce = 150,        -- ms of quiet before pushing an edit
    filetypes = { 'markdown' }, -- eligible without :Preview!
    auto_close = true,     -- close preview when its buffer unloads
    auto_stop = true,      -- stop server with the last preview
    open_browser = true,   -- false: only print the URL
    math = true,           -- $…$ / $$…$$ / ```math via KaTeX; also accepts
                           -- { macros = { ['\\RR'] = '\\mathbb{R}' } }
    mermaid = true,        -- ```mermaid diagrams
    emoji = true,          -- :shortcode: expansion
    wikilinks = true,      -- [[page]] links + ![[image]] embeds
    reload_images = true,  -- refresh images in previews on disk change
    scroll_sync = true,    -- see |mdpv-sync|; true | false | 'both'
  })
<
==============================================================================
5. LUA API                                                       *mdpv-api*

  require('mdpv').open({bufnr}, {opts})                          *mdpv.open()*
      Open a preview. {bufnr} defaults to the current buffer; {opts.force}
      skips the filetype check. Returns the preview URL or nil.

  require('mdpv').close({bufnr})                                *mdpv.close()*
      Close the preview for {bufnr} (default: current buffer).

  require('mdpv').toggle({bufnr})                              *mdpv.toggle()*
      Open a preview if none is live for {bufnr}, otherwise close it.

  require('mdpv').stop()                                         *mdpv.stop()*
      Close all previews and stop the server.

  require('mdpv').url({bufnr})                                    *mdpv.url()*
      The preview URL for a buffer, if one is live.

  require('mdpv').list()                                         *mdpv.list()*
      Returns { { bufnr, title, url }, ... } for all active previews.

6. SCROLL SYNC                                                  *mdpv-sync*

With `scroll_sync = true` (default) the page follows your cursor line,
interpolating between blocks for smooth tracking. The block under the cursor
carries a subtle accent bar in the left gutter, the outline (|mdpv-outline|)
highlights the enclosing heading, and when the cursor sits on a heading line
the page's URL hash follows it — copy the address bar for a deep link.
"Follow cursor" in the floating menu toggles all of this (remembered like
every menu choice, see |mdpv-menu|).

The reverse direction — scrolling the page moves the Neovim cursor to the
line under the upper third of the viewport — is the menu's "Move cursor on
scroll" switch, off by default; `scroll_sync = 'both'` defaults it to on
instead. The two switches are independent, and echo suppression on both ends
prevents feedback loops. `scroll_sync = false` turns scroll sync off
entirely, in both directions.

7. THE PREVIEW PAGE                                             *mdpv-page*

Content renders in the browser (markdown-it plus GitHub markup passes), so
Neovim never parses markdown; edits are debounced, streamed over SSE, and
DOM-diffed into the page — images don't reload, open <details> stay open,
and unchanged math, diagrams, and highlighted code are not re-rendered.

ALERTS & CALLOUTS                                          *mdpv-callouts*

GitHub's five alerts (`> [!NOTE]` …) render exactly as GitHub does, and the
full Obsidian callout set (obsidian.md/help/callouts) rides on top: 13 types
plus their aliases, custom titles after the marker, folding (`[!faq]-`
starts collapsed, `[!tip]+` starts expanded), and nesting. Where the two
vocabularies collide (`important`, `caution`), GitHub wins; unknown types
stay plain blockquotes.

WIKILINKS                                                 *mdpv-wikilinks*

`[[page]]` resolves to `page.md` next to the file, with `[[page|alias]]`,
`[[page#heading]]`, and image embeds `![[img.png]]`. Set
`wikilinks = false` to render them literally, like GitHub outside wikis.

TASK LISTS                                               *mdpv-checkboxes*

Checkboxes in a live preview are clickable: ticking one flips the
`[ ]`/`[x]` on that source line in the buffer (which must be 'modifiable').
Statically rendered .md files keep them read-only, like on GitHub.

CODE                                                           *mdpv-code*

Fenced code is highlighted with highlight.js (loaded lazily, on the first
block that needs it) and every block shows a copy button on hover.

MATH & DIAGRAMS                                                *mdpv-math*

KaTeX and Mermaid are vendored but fetched only when a document uses them.
`math` accepts a table of KaTeX options — e.g. macros, see |mdpv-config|.
Rendered diagrams show pan/zoom controls on hover: zoom in/out, drag to pan
while zoomed, double-click (or the reset button) to restore.

FILES & LINKS                                                 *mdpv-files*

Relative images and links resolve against the file's directory (and its
subtree; links pointing above it are not served). A relative link to
another `.md` file renders as a page too; append `?raw` for the raw file.
Media is served with byte ranges, so video and audio can seek.

LIVE IMAGE RELOAD                                            *mdpv-images*

Images and media the page has loaded are watched on disk; regenerating one
(a screenshot, a rendered diagram) refreshes it in place in every open
preview. Disable with `reload_images = false`.

THE FLOATING MENU                                              *mdpv-menu*

A floating button (bottom right by default; drag it to any corner) shows
the connection state and opens the page menu. Sync (live previews only):
follow cursor, move cursor on scroll. View: outline, full width, theme
(auto/light/dark). Plus go to top.

Every choice — corners included — is remembered across sessions: the page
keeps it in the browser and mirrors it to a small state file on the editor
side (`stdpath("state")/mdpv-prefs.json`), so the next session's page picks
up your last settings even though the server sits on a new port by then
(which browsers treat as a different site).

THE OUTLINE                                                 *mdpv-outline*

The document outline floats over the page collapsed into a slim rail of
dashes — one per heading, longer for higher levels, with the section you
are reading accented (scroll-spied). Hovering the rail expands it in place
into the full heading list, where levels read by weight and shade (h1
heaviest) and indentation. Clicking an entry jumps to it, and moving the
pointer away collapses the list back to the rail. On by default; switch it
off (and back on) from the menu. Drag it to park it in any corner; when it
meets the menu button in a corner, it steps aside so the two never overlap.

SECURITY                                                   *mdpv-security*

Raw HTML is sanitized with DOMPurify; pages carry a strict CSP; the server
binds localhost only and every route is token-gated. Path traversal (`..`)
is rejected on all file routes.
